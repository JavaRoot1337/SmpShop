# SmpShop: инструкция для сервера

SmpShop - плагин магазинов на сундуках для CanvasMC 26.2 и Folia 26.2. Требуется Java 25. База данных локальная, интеграции Телеграма и Дискорда необязательны.

Версия плагина: `1.0`. Основная команда: `/smpshop`, алиас: `/shop`.

Эта инструкция описывает настройку и ежедневное использование плагина. Полное описание структуры и технических ограничений находится в `README.md`.

Техническое описание: [README.md](README.md).

## Файлы плагина

После первого запуска сервер создаёт:

```text
plugins/SmpShop/
├── config.yml
├── message.yml
├── message_other.yml
├── message_tg.yml
├── message_ds.yml
└── shops.db
```

`config.yml` содержит технические настройки, `message.yml` - сообщения Minecraft, `message_other.yml` - русские технические сообщения и ошибки сервера, а `message_tg.yml` и `message_ds.yml` - формат уведомления о продаже. `shops.db` нельзя редактировать вручную во время работы сервера.

Готовый файл плагина называется `SmpShop-1.0.jar` и кладётся в папку `plugins`. После замены JAR перезапустите сервер. Сборка из проекта:

```text
gradlew.bat clean build
```

Файл появится в `build/libs/SmpShop-1.0.jar`.

## Быстрая настройка

В чистом конфиге интеграции выключены:

```yaml
integrations:
  telegram:
    enabled: false
    bot-token: ''
  discord:
    enabled: false
```

Для обычных магазинов достаточно запустить сервер и выдать игрокам `smpshop.use`. Все сообщения и параметры уже имеют значения по умолчанию.

Не добавляйте в Git токен Телеграма и вебхук Дискорда. Если токен уже попал в общий репозиторий или был отправлен другому человеку, его нужно заменить через BotFather.

## Команды игрока

| Команда | Результат |
| --- | --- |
| `/smpshop` | открывает список помощи |
| `/smpshop help` | открывает список помощи |
| `/smpshop set <цена>` | запускает установку магазина |
| `/smpshop balance` | открывает баланс руды |
| `/smpshop delete` | подготавливает удаление своего магазина |
| `/smpshop list` | показывает свои магазины |
| `/smpshop link tg` | создаёт привязку Телеграма |
| `/smpshop link ds webhook <url>` | сохраняет вебхук Дискорда для своих продаж |
| `/smpshop link max` | показывает отдельное настроенное сообщение |

`/shop` является алиасом `/smpshop`. Если команда введена без аргументов, с неизвестной командой или с неправильным числом аргументов, плагин снова показывает помощь.

### Установка

1. Введите `/smpshop set 10` или другую цену.
2. Получите сообщение о сохранённой цене.
3. В течение времени из `pending-placement-timeout-seconds` нажмите ПКМ по обычному сундуку.

Обычный и двойной сундук поддерживаются. Для двойного сундука проверяются обе половины. Если сундук уже зарегистрирован полностью или частично, установка отменяется. Магазин закрепляется за UUID игрока, а не за его текущим ником.

Цена - это количество АР за один товарный слот. Покупатель получает весь стек из выбранного слота. У владельца может быть до `max-per-player` магазинов. При праве `smpshop.plus` используется отдельный лимит `plus-max-per-player`.

### Заполнение сундука

Владелец открывает сундук и кладёт туда любой товар. Владелец может также забрать или переместить любой предмет. Пока другой игрок покупает товар, открыть этот же магазин владельцу нельзя.

Покупатель не забирает товар из сундука напрямую. Он открывает магазин, кладёт оплату в свободные слоты и нажимает по нужному товару.

### Удаление

Для своего магазина:

1. Введите `/smpshop delete`.
2. Нажмите ПКМ по своему магазину.

Для любого магазина администратор использует `/smpshop remove`, если у него есть `smpshop.admin.remove`. При удалении остаётся весь товар и содержимое сундука. Выплата или возврат за удаление не создаются.

## Покупка и оплата

Плагин принимает только:

- `DIAMOND_ORE` (алмазная руда), один предмет равен 1 АР;
- `DEEPSLATE_DIAMOND_ORE` (глубинная алмазная руда), один предмет равен 1 АР.

Руда не меняется между типами. Можно оплатить цену любой комбинацией, например 10 обычной рудой или 6 обычной и 4 глубинной.

При открытии сундука плагин запоминает товарные слоты и свободные слоты оплаты. Свободные слоты становятся местом оплаты. В них нельзя положить обычный предмет. Один магазин блокируется для второго покупателя до закрытия первой сессии.

Покупка возможна, если:

- товарный слот не изменился;
- в слотах оплаты достаточно двух разрешённых руд;
- в инвентаре покупателя хватает места для всего стека;
- магазин не удалён и сессия ещё активна.

После покупки списывается ровно цена магазина, покупателю выдаётся весь стек, а продавцу начисляется фактическая обычная и глубинная руда. В сообщениях сумма - это цена покупки, а не количество предметов товара.

Если закрыть сундук с неиспользованной оплатой, руда возвращается. Сначала она добавляется в инвентарь. При переполнении остаток выбрасывается рядом с игроком. При отключении игрока остаток записывается в его баланс SQLite.

## Уведомления и звуки

При успешной продаже онлайн-продавец получает сообщение о магазине, товаре и сумме. Если продавец вышел, сумма сохраняется в SQLite отдельной записью уведомления, когда `notifications.offline-enabled: true`.

При входе плагин объединяет все непрочитанные записи продавца в одно сообщение `offline-sales`, если `notifications.join-message-enabled: true`. После отправки запись отмечается доставленной, поэтому одно уведомление не повторяется.

После покупки покупатель слышит звук из `sounds.buyer-purchase`. Продавец слышит звук из `sounds.seller-sale` вместе с сообщением о продаже. Для каждого звука отдельно настраиваются `enabled`, `sound`, `volume` и `pitch`.

Например:

```yaml
sounds:
  seller-sale:
    enabled: true
    sound: entity.player.levelup
    volume: 1.0
    pitch: 0.9
  buyer-purchase:
    enabled: true
    sound: block.vault.insert_fail
    volume: 1.0
    pitch: 1.0

notifications:
  offline-enabled: true
  join-message-enabled: true
```

Имена звуков пишутся с точками. Неизвестное имя не ломает покупку, а только отключает этот звук и записывается в лог сервера.

## Меню баланса

`/smpshop balance` открывает меню на 27 слотов. В нём лежат настоящие ванильные иконки:

- `DIAMOND_ORE` - алмазная руда;
- `DEEPSLATE_DIAMOND_ORE` - глубинная алмазная руда.

Если конкретного баланса нет, соответствующая иконка не показывается. Это не заблокированный декоративный слот.

Действия:

- левый клик: забрать весь видимый стек;
- правый клик: забрать половину;
- shift-клик: вывести предмет в инвентарь.

Из нижнего инвентаря нельзя положить предмет в меню. Drag, double-click, number keys, hotbar swap и попытки забрать декоративную кнопку отменяются. При переполнении инвентаря непоместившийся остаток не пропадает, а возвращается на баланс.

## Меню магазинов

`/smpshop list` открывает магазины текущего игрока. Администратор с `smpshop.admin.list` может открыть `/smpshop list <игрок>`.

Настройка `shop.menu-size` принимает `36` или `54`:

- 36 слотов: 27 карточек магазинов;
- 54 слота: 45 карточек магазинов.

Последние 9 слотов всегда оставляются навигации. Магазин не может занять эти слоты. Стрелка назад находится в первом слоте нижнего ряда, стрелка вперёд - в последнем. Стрелка показывается только когда соответствующая страница существует.

Иконка карточки выбирается из содержимого сундука по самому большому количеству предмета. Две руды валюты игнорируются. Пустой магазин показывается через `BARRIER` (барьер).

На карточке есть:

- номер магазина;
- последнее известное имя владельца;
- координаты;
- заработанная сумма;
- количество проданных предметов;
- цена одного товарного слота.

## Логирование в Телеграме

Бот Телеграма работает на сервере внутри плагина. Внешний хостинг не нужен. Нужен доступ сервера к Bot API Телеграма.

Настройка:

```yaml
integrations:
  telegram:
    enabled: true
    bot-token: 'токен бота'
    poll-interval-seconds: 2
    link-code-timeout-seconds: 300
    referal-bot: true
    user-bot: 'имя_бота_без_@'
```

1. Введите в игре `/smpshop link tg`.
2. При `referal-bot: true` нажмите на настроенный текст ссылки в чате.
3. Телеграм откроет бота и передаст ему `/start <код>`.
4. Плагин привяжет ID чата Телеграма к UUID игрока.

Если `referal-bot: false`, игрок получает 16-значный код. Нажатие на код копирует `/code <код>`, после чего его можно отправить боту. Бот понимает `/code <16-значный код>` и `/start <код>`.

Код случайный, одноразовый и ограничен сроком из `link-code-timeout-seconds`. В SQLite записывается хеш, а не исходный код. ID чата Телеграма сохраняется после перезапуска.

Телеграм получает только продажи. Формат задаётся в `message_tg.yml`:

```yaml
sale: "Новая продажа! Магазин %shop%: %item% x%items% за %amount% АР"
```

Доступные плейсхолдеры: `%shop%`, `%item%`, `%items%`, `%amount%`.

## Логирование в Дискорд

Бот Дискорда не используется. Для каждого игрока сохраняется отдельный вебхук.

1. Включите `integrations.discord.enabled: true`.
2. Введите `/smpshop link ds webhook <url>`.
3. После сообщения об успешном сохранении продажи из магазинов игрока будут отправляться на этот адрес.

После `link ds` автодополнение предлагает `webhook`. Ссылка автоматически не вставляется: её нужно указать полностью.

Вебхук хранится в таблице `discord_webhooks` по UUID и не слетает после перезапуска. Повторная команда заменяет сохранённый адрес. В конфиге нет общего вебхука.

Формат продажи находится в `message_ds.yml`:

```yaml
sale: "Новая продажа\nМагазин: %shop%\nТовар: %item% x%items%\nСумма: %amount% АР"
```

Доступны `%shop%`, `%item%`, `%items%`, `%amount%`. Тестовые отправки отсутствуют: вебхук вызывается только при реальной покупке.

## Настройки

```yaml
shop:
  min-price: 1 #минимальная цена магазина
  max-price: 2304 #максимальная цена магазина
  max-per-player: 10 #обычный лимит магазинов
  plus-max-per-player: 50 #увеличенный лимит магазинов
  menu-size: 36 #размер меню списка магазинов
  allowed-menu-sizes:
    - 36 #размер меню на 27 магазинов
    - 54 #размер меню на 45 магазинов
  pending-placement-timeout-seconds: 60 #время ожидания установки магазина

storage:
  sqlite-file: shops.db #имя файла базы данных
  transaction-timeout-seconds: 10 #таймаут транзакции базы данных

sounds:
  seller-sale:
    enabled: true #включить звук продажи
    sound: entity.player.levelup #звук продажи
    volume: 1.0 #громкость звука продажи
    pitch: 0.9 #тон звука продажи
  buyer-purchase:
    enabled: true #включить звук покупки
    sound: block.vault.insert_fail #звук покупки
    volume: 1.0 #громкость звука покупки
    pitch: 1.0 #тон звука покупки

notifications:
  offline-enabled: true #сохранять уведомления для офлайн-продавца
  join-message-enabled: true #показывать уведомление при входе продавца

integrations:
  telegram:
    enabled: false #включить телеграм
    bot-token: '' #токен телеграм-бота
    poll-interval-seconds: 2 #интервал опроса телеграма
    link-code-timeout-seconds: 300 #срок действия кода телеграма
    referal-bot: true #отправлять реферальную ссылку вместо копирования кода
    user-bot: '' #имя телеграм-бота без символа @
  discord:
    enabled: false #включить дискорд через вебхук
```

Параметр `buyer-lock-timeout-seconds` удалён. Покупательский lock не истекает по таймеру: он снимается после закрытия inventory, отключения игрока или выключения плагина. `flush-interval-seconds` и `default-price` также удалены. Разделы `sounds` и `notifications` используются текущей версией.

## Плейсхолдеры сообщений

В `message.yml` разрешены следующие значения:

| Плейсхолдер | Что выводит |
| --- | --- |
| `%min%`, `%max%` | границы цены |
| `%limit%` | лимит магазинов игрока |
| `%price%` | цена магазина |
| `%page%` | номер страницы списка |
| `%id%` | числовой ID магазина |
| `%owner%` | имя владельца |
| `%x%`, `%y%`, `%z%` | координаты сундука |
| `%earned%` | заработанная сумма |
| `%sold%` | число проданных предметов |
| `%shop%` | номер магазина |
| `%item%` | материал товара |
| `%items%` | количество предметов в стеке |
| `%amount%` | сумма оплаты |

Для диагностических сообщений в `message_other.yml` используются `%sound%`, `%status%`, `%error%`, `%resource%` и `%key%`. Они нужны только для записей в серверный лог и технических ошибок плагина. Сообщения и ошибки SQLite остаются техническими строками базы данных.

`%amount%` в сообщении `offline-sales` означает общую сумму продаж, накопленную за время отсутствия игрока. В `message_tg.yml` и `message_ds.yml` используются `%shop%`, `%item%`, `%items%` и `%amount%`.

Код Телеграма вставляется программно, поэтому `%code%` в сообщениях не используется. Все строки с цветами Minecraft поддерживают `&`.

## Защита и ограничения

Зарегистрированный сундук нельзя сломать, взорвать, сдвинуть поршнем или использовать как источник/получатель автоматической передачи. Воронки и вагонетки с воронкой блокируются рядом с магазином. Владелец сохраняет обычный ручной доступ к сундуку, а покупатель работает только через правила торговой сессии.

Голограмм у сундуков нет. Предметы товара не копируются в отдельную базу. Если физический сундук потерян вместе с миром, SQLite не может восстановить его содержимое.

## Хранение и перезапуск

SQLite находится в `plugins/SmpShop/shops.db`. Плагин применяет миграции V1-V6 и использует одну асинхронную очередь записи. Данные не ждут периодического flush: каждая запись отправляется в базу сразу. Включены WAL и `synchronous=FULL`.

После рестарта сохраняются:

- магазины и их ID;
- UUID владельцев и последнее известное имя в игре;
- цена и статистика продаж;
- баланс двух видов руды;
- ID чата Телеграма;
- использованные и активные коды привязки;
- вебхук Дискорда игрока.

Плагин не хранит `Player` в долгоживущих коллекциях. Все обращения к миру, сундукам и инвентарям выполняются через соответствующий scheduler, а база и сеть не блокируют region thread.

## Проверка после установки

Проверьте по порядку:

1. `/smpshop help` выводит все команды.
2. `/smpshop set 10` создаёт магазин после ПКМ по сундуку.
3. Второй магазин не регистрируется на той же половине или соседней половине двойного сундука.
4. Владелец может заполнить и очистить сундук.
5. Покупатель принимает только две руды, смешанная оплата списывается точно.
6. Неиспользованная руда возвращается после закрытия сундука.
7. `/smpshop balance` показывает реальные иконки руды, а перенос из инвентаря в GUI отменяется.
8. `/smpshop list` открывает правильный размер и навигацию.
9. Воронка и вагонетка с воронкой не забирают товар.
10. После `/smpshop link tg` работает `/start` или `/code`.
11. После `/smpshop link ds webhook <url>` на вебхук приходит только продажа.
12. После перезапуска SQLite восстанавливает магазины и привязки.
