# SmpShop

SmpShop добавляет магазины на обычных сундуках. Плагин рассчитан на CanvasMC 26.2 и Folia 26.2, Java 25.

Краткая инструкция для сервера: [READMERU.md](READMERU.md).

Версия плагина: `1.0`. Имя JAR: `SmpShop-1.0.jar`. Основная команда: `/smpshop`, алиас: `/shop`.

Плагин не заявляет поддержку Paper, Spigot или обычного Bukkit. В коде нет NMS, CraftBukkit, reflection и `BukkitScheduler`. Операции с сундуками выполняются в region-контексте, операции с игроком и его инвентарём - в entity-контексте, SQLite и HTTP - асинхронно.

## Установка

1. Соберите проект или возьмите готовый `SmpShop-1.0.jar`.
2. Положите JAR в папку `plugins` сервера.
3. Запустите сервер. Плагин создаст `plugins/SmpShop/` и локальную базу `shops.db`.
4. Откройте созданные `config.yml`, `message.yml` и `message_other.yml` и измените нужные значения.
5. После изменения JAR перезапустите сервер. Для изменения конфигурации можно использовать `/smpshop reload`.

Сборка из исходников:

```text
gradlew.bat clean build
```

Результат находится в `build/libs/SmpShop-1.0.jar`. Canvas API не включается в JAR. SQLite-драйвер и Gson включаются в JAR, Gson переносится в отдельный пакет.

## Команды

Основная команда имеет алиас `/shop`. Если ввести `/smpshop` без аргументов, `help` или неизвестный набор аргументов, плагин покажет список команд.

| Команда | Кто использует | Назначение |
| --- | --- | --- |
| `/smpshop` | игрок | показать помощь |
| `/smpshop help` | игрок | показать помощь |
| `/smpshop set <цена>` | игрок | начать установку своего магазина |
| `/smpshop balance` | игрок | открыть баланс руды |
| `/smpshop delete` | владелец | удалить свой магазин после ПКМ по нему |
| `/smpshop remove` | администратор | удалить любой магазин после ПКМ по нему |
| `/smpshop list` | игрок | открыть свои магазины |
| `/smpshop list <игрок>` | администратор | открыть магазины указанного игрока |
| `/smpshop link tg` | игрок | получить код или ссылку привязки Telegram |
| `/smpshop link ds webhook <url>` | игрок | сохранить Discord webhook для своих продаж |
| `/smpshop link max` | игрок | показать настроенное специальное сообщение |
| `/smpshop reload` | администратор | перечитать конфигурацию и сообщения |

Команды доступны только игрокам. Сообщения консоли о том, что команда доступна только игроку, настраиваются в `message.yml`.

### Создание магазина

Игрок выполняет `/smpshop set <цена>`. Цена должна быть целым числом в пределах `shop.min-price` и `shop.max-price`. После этого в течение `shop.pending-placement-timeout-seconds` секунд нужно нажать ПКМ по обычному сундуку.

При установке плагин проверяет обе половины двойного сундука. Если хотя бы одна координата уже принадлежит магазину, установка отменяется. Зарегистрированный сундук получает имя магазина. Товар и оплата физически хранятся в сундуке, отдельной копии товарного инвентаря в SQLite нет.

Цена магазина - это сумма руды за один покупаемый товарный слот. Покупатель получает весь `ItemStack`, который находился в выбранном слоте. Лимит магазинов считается по UUID владельца, поэтому смена ника не создаёт новые магазины и не лишает доступа к старым.

Обычный лимит берётся из `shop.max-per-player`. При наличии `smpshop.plus` используется `shop.plus-max-per-player`.

### Удаление магазина

После `/smpshop delete` владелец нажимает ПКМ по своему магазину. Проверяется UUID владельца. После удаления регистрация снимается, имя, установленное плагином, очищается, а содержимое сундука остаётся на месте.

`/smpshop remove` работает так же, но требует `smpshop.admin.remove` и позволяет удалить магазин любого владельца. Товар не удаляется, возврат или выплата при удалении не создаются.

### Баланс

`/smpshop balance` открывает настоящее инвентарное меню на 27 слотов. Если на балансе есть руда, в меню лежат ванильные предметы `DIAMOND_ORE` и `DEEPSLATE_DIAMOND_ORE` с реальным количеством.

Из меню можно забрать руду:

- левый клик забирает весь видимый стек;
- правый клик забирает половину, округлённую вверх;
- shift-клик также запускает вывод в инвентарь игрока.

Положить руду из инвентаря обратно в меню нельзя. Перемещение предметов в верхний инвентарь, drag, double-click, number keys и hotbar swap блокируются. Декоративные элементы не выдаются. Если в инвентаре не хватило места, невыданное количество возвращается на баланс.

Баланс двух видов руды хранится раздельно в SQLite. При продаже начисляется фактический состав оплаты: обычная и глубинная руда не конвертируются друг в друга.

### Список магазинов

`/smpshop list` открывает список магазинов отправителя. Команда `/smpshop list <игрок>` доступна с `smpshop.admin.list`; имя используется только для поиска OfflinePlayer, постоянная связь хранится по UUID.

Размер меню задаётся `shop.menu-size` и должен быть одним из значений в `shop.allowed-menu-sizes`:

- 36 слотов: 27 магазинов и 9 слотов навигации;
- 54 слота: 45 магазинов и 9 слотов навигации.

Нижний ряд всегда занят навигацией. Кнопка "Назад" появляется слева на нижнем ряду после первой страницы, кнопка "Вперёд" - справа, если есть следующая страница. Магазины не используют эти слоты.

Иконка магазина выбирается по самому многочисленному предмету в физическом сундуке. `DIAMOND_ORE` и `DEEPSLATE_DIAMOND_ORE` при выборе не учитываются. Если других предметов нет, используется `BARRIER`.

Клик по магазину открывает его через безопасный region/entity scheduler. В карточке выводятся номер, владелец, координаты, заработанная сумма, количество проданных предметов и цена за один слот.

## Валюта и покупка

Валюта плагина фиксирована в коде:

- `DIAMOND_ORE` - 1 АР за предмет;
- `DEEPSLATE_DIAMOND_ORE` - 1 АР за предмет.

Другие материалы валютой не считаются. Конвертации между двумя рудами нет. Оплата может быть смешанной: например, 6 `DIAMOND_ORE` и 4 `DEEPSLATE_DIAMOND_ORE` дают 10 АР.

При открытии магазина покупателя плагин фиксирует содержимое сундука и пустые payment-слоты. Магазин блокируется для других покупателей на всё время открытой сессии. Владелец в это время тоже не может открыть свой сундук, чтобы не столкнуть действия владельца и покупателя.

Покупатель может:

- положить в пустые payment-слоты только две разрешённые руды;
- нажать по товарному слоту;
- купить весь стек товара, если хватает оплаты и места в инвентаре;
- продолжать покупать другие слоты в той же сессии.

Покупатель не может забирать товар обычным кликом, менять товар местами, класть обычные предметы, использовать drag, shift-click, number keys, double-click, hotbar swap или drop для обхода правил. Если товарный слот изменился после открытия, покупка не проводится.

Покупка не проходит, если:

- внесено меньше цены магазина;
- для полного стека товара нет места в инвентаре;
- магазин удалён;
- открытая сессия больше не принадлежит этому inventory;
- выбранный слот отличается от зафиксированного.

После успешной покупки плагин списывает ровно цену, удаляет товарный стек, выдаёт покупателю весь стек, увеличивает счётчики магазина и начисляет продавцу фактическую руду. Продавец получает сообщение в игре, если находится онлайн. В Telegram и Discord отправляется только событие продажи.

При закрытии сундука неиспользованная руда возвращается игроку. Сначала используется `Inventory#addItem`, остаток выбрасывается рядом с игроком через entity scheduler. При отключении игрока остаток зачисляется в его SQLite-баланс. Активные сессии закрываются также при выключении плагина.

## Защита магазинов

Плагин защищает зарегистрированные сундуки и обе половины двойного сундука от:

- ломания;
- взрывов блоков и сущностей;
- урона взрывом визера;
- перемещения поршнями;
- перемещения предметов через воронки;
- извлечения предметов через вагонетку;
- автоматического внесения предметов;
- подбора предметов воронкой;
- установки воронки рядом с магазином;
- установки вагонетки с воронкой рядом с магазином.

`InventoryMoveItemEvent` и `InventoryPickupItemEvent` отменяются, если источник или назначение связано с магазином. Защита проверяет соседние блоки, поэтому воронку нельзя поставить непосредственно рядом с магазином и использовать для обхода защиты.

Голограмм у магазинов нет. Отдельной механики голограмм плагин не создаёт.

Владелец может открывать свой магазин и пользоваться сундуком обычным способом: добавлять, забирать и перемещать любые предметы. Во время сессии покупателя доступ владельца временно блокируется.

## Конфигурация

Файл: `plugins/SmpShop/config.yml`.

```yaml
shop:
  min-price: 1 #минимальная цена магазина
  max-price: 2304 #максимальная цена магазина
  max-per-player: 10 #обычный лимит магазинов
  plus-max-per-player: 50 #увеличенный лимит магазинов
  menu-size: 36 #размер меню списка магазинов
  allowed-menu-sizes:
    - 36 #размер меню на 27 магазинов
    - 54 #размер меню на 45 магазинов
  pending-placement-timeout-seconds: 60 #время ожидания установки магазина

storage:
  sqlite-file: shops.db #имя файла базы данных
  transaction-timeout-seconds: 10 #таймаут транзакции базы данных

sounds:
  seller-sale:
    enabled: true #включить звук продажи
    sound: entity.player.levelup #звук продажи
    volume: 1.0 #громкость звука продажи
    pitch: 0.9 #тон звука продажи
  buyer-purchase:
    enabled: true #включить звук покупки
    sound: block.vault.insert_fail #звук покупки
    volume: 1.0 #громкость звука покупки
    pitch: 1.0 #тон звука покупки

notifications:
  offline-enabled: true #сохранять уведомления для офлайн-продавца
  join-message-enabled: true #показывать уведомление при входе продавца

integrations:
  telegram:
    enabled: false #включить телеграм
    bot-token: '' #токен телеграм-бота
    poll-interval-seconds: 2 #интервал опроса телеграма
    link-code-timeout-seconds: 300 #срок действия кода телеграма
    referal-bot: true #отправлять реферальную ссылку вместо копирования кода
    user-bot: '' #имя телеграм-бота без символа @
  discord:
    enabled: false #включить дискорд через вебхук
```

`referal-bot` написан именно так, потому что это имя настройки, используемое плагином.

`storage.sqlite-file` задаёт имя локального файла внутри папки данных плагина. Записи проходят через одну асинхронную последовательную очередь. Периодического flush-таймера нет: изменения отправляются в SQLite сразу, используется WAL и `synchronous=FULL`.

Следующие старые настройки удалены и больше не работают: `shop.default-price`, `shop.buyer-lock-timeout-seconds`, `storage.flush-interval-seconds`, а также общий Discord webhook. Разделы `sounds` и `notifications` используются текущей версией. Старые удалённые ключи убираются из существующего `config.yml` миграцией конфигурации.

## Сообщения и плейсхолдеры

Игровые сообщения находятся в `plugins/SmpShop/message.yml`. Технические сообщения сервера и ошибки интеграций находятся в `plugins/SmpShop/message_other.yml` и пишутся по-русски без цветовых кодов. Форматы сообщений Telegram и Discord находятся отдельно в `message_tg.yml` и `message_ds.yml`. Значения можно менять без изменения Java-кода.

Используемые плейсхолдеры `message.yml`:

| Плейсхолдер | Где используется | Значение |
| --- | --- | --- |
| `%min%` | `price-range` | минимальная цена |
| `%max%` | `price-range` | максимальная цена |
| `%limit%` | `shop-limit` | применённый лимит магазинов |
| `%price%` | `placement-pending`, `shop-created`, `list-price` | цена магазина |
| `%page%` | `list-title` | текущая страница |
| `%id%` | `list-shop-name` | числовой ID магазина |
| `%owner%` | `list-owner` | последнее известное имя владельца |
| `%x%`, `%y%`, `%z%` | `list-coordinates` | координаты магазина |
| `%earned%` | `list-earned` | заработанная сумма |
| `%sold%` | `list-sold` | количество проданных предметов |
| `%shop%` | `sale-chat` | номер магазина с символом `#` |
| `%item%` | `sale-chat`, `purchase-success` | имя материала товара |
| `%items%` | `sale-chat`, `purchase-success` | количество предметов в купленном стеке |
| `%amount%` | `sale-chat`, `purchase-success` | сумма списанной оплаты |
| `%amount%` | `offline-sales` | сумма продаж, накопленная пока игрок был офлайн |

В сообщениях для получения кода (`link-code-prefix` и `link-code-suffix`) код добавляется самим плагином, поэтому `%code%` там не нужен.

В `message_other.yml` находятся диагностические сообщения конфигурации, уведомлений, звуков и внешних интеграций. Они используются в серверном логе без цветового преобразования. SQL-ошибки и технические сообщения SQLite остаются в коде базы данных.

Плейсхолдеры `message_other.yml`: `%sound%` - имя неизвестного звука, `%status%` - HTTP-код ответа, `%error%` - текст исключения, `%resource%` - имя файла сообщений, `%key%` - имя отсутствующего ключа.

Для Telegram-ссылки используются `telegram-referral-prefix` и `telegram-referral-suffix`. Сам URL не показывается отдельным текстом. К сообщению прикрепляется кликабельная ссылка, а текст, например `(нажмите на ссылку)`, задаётся в `telegram-referral-suffix`.

## Уведомления и звуки

При продаже продавцу, который находится онлайн, отправляется `sale-chat`. Если продавец офлайн и `notifications.offline-enabled: true`, плагин сохраняет сумму продажи в таблицу `notifications`. При следующем входе, если `notifications.join-message-enabled: true`, все накопленные записи объединяются в одно сообщение `offline-sales` и после успешной отправки отмечаются доставленными. Повторно они не показываются.

Для покупателя после успешной покупки проигрывается `sounds.buyer-purchase`. Для продавца при доставке сообщения о продаже проигрывается `sounds.seller-sale`. Каждый звук можно отключить отдельно через `enabled`, а также изменить его имя, громкость и тон.

Имена звуков указываются в формате Minecraft с точками, например `entity.player.levelup` или `block.vault.insert_fail`. Плагин преобразует их в Bukkit-имя. Неизвестное имя отключает только этот звук и записывается в лог.

## Telegram

Бот Telegram запускается внутри плагина на сервере. Для получения обновлений используется асинхронный polling. Отдельный хостинг бота не требуется, но сервер должен иметь доступ к Telegram Bot API.

В `config.yml` нужно указать:

```yaml
integrations:
  telegram:
    enabled: true
    bot-token: 'токен от BotFather'
    poll-interval-seconds: 2
    link-code-timeout-seconds: 300
    referal-bot: true
    user-bot: 'имя_бота_без_@'
```

После `/smpshop link tg`:

- при `referal-bot: true` игрок получает кликабельный текст со ссылкой `https://t.me/<user-bot>?start=<код>`;
- при `referal-bot: false` игрок получает 16-значный код, который можно нажать для копирования `/code <код>`.

Бот принимает `/start <код>` и `/code <код>`. Код состоит из 16 цифр, создаётся криптографически случайно, действует ограниченное время и используется один раз. В базе хранится только SHA-256 хеш кода. Привязанный Telegram chat ID хранится в SQLite и не сбрасывается после перезапуска.

Telegram используется только для логов продаж. Формат находится в `message_tg.yml`:

```yaml
sale: "Новая продажа! Магазин %shop%: %item% x%items% за %amount% АР"
```

Внешний файл поддерживает плейсхолдеры `%shop%`, `%item%`, `%items%` и `%amount%`. Тестовые сообщения не используются.

Если токен пустой, неверный или Telegram временно недоступен, плагин продолжает работу с магазинами. Ошибка интеграции не должна отключать остальные функции.

## Discord

Discord работает только через webhook. Discord-бот, bot token и Discord API-клиент для входа в аккаунт не используются.

1. Включите `integrations.discord.enabled: true`.
2. Выполните `/smpshop link ds webhook <url>`.
3. После сохранения webhook плагин будет отправлять на него продажи из магазинов этого игрока.

После `link ds` tab completer предлагает аргумент `webhook`. Сам URL автоматически не подставляется.

Webhook хранится в SQLite по UUID игрока и загружается после перезапуска. В конфигурации нет общего поля webhook: каждый игрок задаёт собственный адрес. Один игрок может заменить свой адрес повторным выполнением команды.

Файл `message_ds.yml` содержит только формат продажи:

```yaml
sale: "Новая продажа\nМагазин: %shop%\nТовар: %item% x%items%\nСумма: %amount% АР"
```

Используются `%shop%`, `%item%`, `%items%` и `%amount%`. Тестовых сообщений нет. URL webhook является секретом, его нельзя публиковать в Git, чате или документации.

## Права

| Permission | По умолчанию | Назначение |
| --- | --- | --- |
| `smpshop.use` | `true` | доступ к основной команде |
| `smpshop.balance` | `true` | открытие баланса и вывод руды |
| `smpshop.link` | `true` | Telegram-код и Discord webhook |
| `smpshop.plus` | `op` | увеличенный лимит магазинов |
| `smpshop.admin.remove` | `op` | удаление любого магазина |
| `smpshop.admin.list` | `op` | просмотр магазинов другого игрока |
| `smpshop.admin.reload` | `op` | reload конфигурации, сообщений и Telegram |

Все проверки прав выполняются отдельно внутри соответствующей команды. Например, доступ к `/smpshop` сам по себе не выдаёт право на `/smpshop remove`.

## SQLite и данные

База создаётся локально в `plugins/SmpShop/shops.db`. В ней хранятся магазины, балансы, привязки Telegram, коды привязки, Discord webhook и служебные миграции.

Основные таблицы:

- `schema_migrations` - применённые версии схемы;
- `shops` - UUID владельца, имя, мир, координаты обеих половин, цена, статистика и даты;
- `balances` - два независимых баланса руды;
- `social_links` - внешняя платформа, внешний ID и имя;
- `link_codes` - SHA-256 хеш кода, UUID игрока, платформа, срок действия и признак использования;
- `discord_webhooks` - webhook для UUID игрока;
- `notifications` - накопленные офлайн-уведомления о продажах;
- `transactions` - журнал завершённых DB-частей продаж с ключом операции и составом оплаты.

Миграции идут последовательно: V1 магазины, V2 балансы, V3 notifications, V4 social_links и link_codes, V5 transactions, V6 discord_webhooks, V7 ключ операции и индекс журнала.

Физический сундук является источником товарного инвентаря. Плагин не копирует весь сундук в SQLite. Магазины загружаются в runtime-индекс по UUID мира и каноническим координатам.

## Потоки и жизненный цикл

- Region scheduler: блоки, сундуки, двойные сундуки, block state и операции в мире.
- Entity scheduler: инвентарь игрока, открытие GUI, сообщения, звуки и возврат предметов.
- Async scheduler: SQLite, Telegram polling, HTTP webhook и подготовка данных.
- Долгоживущие карты используют UUID, ссылки на `Player` не сохраняются.

При запуске плагин читает конфигурацию и сообщения, проверяет размер меню, запускает SQLite, применяет миграции, загружает магазины и Discord webhook, затем запускает Telegram, если он включён. Пока база не готова, игровые команды получают сообщение о загрузке.

При выключении новые действия прекращаются, сессии покупателей закрываются, остаток оплаты возвращается или начисляется в базу, Telegram останавливается, очередь SQLite завершается, а runtime-состояние очищается.

`/smpshop reload` не пересоздаёт активные сессии. Он перечитывает `message.yml`, `message_other.yml`, `config.yml`, `message_tg.yml`, `message_ds.yml` и перезапускает Telegram polling с новыми настройками. Для обновления самого JAR нужен перезапуск сервера.

## Ограничения текущей версии

- В валюте только два вида руды, изменить их через конфигурацию нельзя.
- Цена задаётся отдельно для каждого магазина.
- Один магазин может быть занят только одной покупательской сессией.
- Содержимое магазина не восстанавливается из SQLite после уничтожения файла мира.
- Офлайн-продавцу начисляется баланс в SQLite, а при включённых настройках также сохраняется объединяемое уведомление о продажах.
- `transactions` фиксирует атомарную DB-часть продажи, но не заменяет физический сундук и не является отдельной копией товара. Полное восстановление физической сделки после аварии требует отдельного recovery-протокола.
- Вебхук и Telegram token нужно хранить только в локальном конфиге сервера.

## Проверка перед установкой на сервер

Проверьте:

1. Сервер запускается на CanvasMC или Folia 26.2 и Java 25.
2. В JAR есть `plugin.yml`, `config.yml`, `message.yml`, `message_other.yml`, `message_tg.yml` и `message_ds.yml`.
3. После запуска появляется `plugins/SmpShop/shops.db`.
4. `/smpshop help` и команды с неверными аргументами показывают помощь.
5. Создание одиночного и двойного сундука работает, конфликтная координата блокируется.
6. Воронка, вагонетка с воронкой, поршень и взрыв не перемещают и не удаляют магазин.
7. Баланс показывает настоящие предметы руды и не принимает депозит из инвентаря.
8. Покупка поддерживает смешанную оплату и возвращает остаток при закрытии.
9. Telegram получает `/start` или `/code`, Discord получает только продажи на сохранённый webhook.
10. После перезапуска магазины, балансы, Telegram chat ID и Discord webhook остаются на месте.
